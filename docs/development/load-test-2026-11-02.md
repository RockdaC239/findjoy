# 本地突发流量压测记录（2026-11-02）

## 环境与边界

- 代码：`test` 分支候选版本（退款复核与积分调整提交之后）。
- 运行：macOS 本机，Node.js 26，Next.js 16.4.3 生产构建（`next start`），本地 PostgreSQL 15.19（127.0.0.1:55440）。
- 隔离：独立 `findjoy_load` 数据库和 3200 端口实例，`FINDJOY_PAYMENTS_MODE=demo`；模型使用 3101 端口的本地 OpenAI 协议替身，不访问外部模型。
- 12 个合成用户，每人 2000 积分；全站生成并发上限 `FINDJOY_GENERATION_MAX_CONCURRENT=4`，连接池默认 5。
- 脚本：`scripts/load-test-seed.mjs`、`scripts/load-test.mjs`。这些结果只证明本地流程和准入保护有效，**不代表生产 4C 服务器或真实模型的容量**。

## 只读负载

```bash
node scripts/load-test-seed.mjs --count=12 --credits=2000 --base=http://127.0.0.1:3200 --out=.data/load-seed.json
node scripts/load-test.mjs --seed=.data/load-seed.json --kind=read --duration=10 --concurrency=20
```

| 指标 | 结果 |
| --- | --- |
| 请求数 / 时长 | 5534 / 10s |
| 吞吐 | 551.5 req/s |
| 状态 | 5534 × 200 |
| 延迟 p50 / p95 / p99 / max | 10 / 15 / 22 / 58 ms |
| 网络或流错误 | 0 |

## 读 + 开局混合负载

```bash
node scripts/load-test.mjs --seed=.data/load-seed.json --kind=mixed --duration=20 --concurrency=12
```

| 指标 | 结果 |
| --- | --- |
| 总请求 / 时长 | 7283 / 20s |
| 吞吐 | 364.0 req/s |
| 读取 | 4859 × 200 |
| 开局 | 240 × 200；1792 × 429；392 × 503 |
| 延迟 p50 / p95 / p99 / max | 7 / 14 / 21 / 36 ms |
| 网络或流错误 | 0 |

429/503 不是未处理异常：分别来自每用户单局在途/每分钟准入限制，以及全站 4 个在途生成的硬上限；接口返回 `Retry-After: 5` 并提示稍后重试。说明过载时没有继续调用模型、没有无限排队。

## 结论与后续

- 本地只读链路和开局准入在合成负载下稳定，未出现 500/502、连接泄漏或流式保存失败。
- 这个结果不能回答“真实模型能承载多少并发”、4C/3.6 GiB 服务器的 CPU/内存余量、真实支付回调重投或长存档增长后的表现。
- 上线前仍需在独立测试服务器用接近生产的 Node/PostgreSQL 配置、真实模型小样本和真实网络做一次受控压测；根据模型延迟与错误率确定最终 `FINDJOY_GENERATION_MAX_CONCURRENT`，保留 CPU、内存和连接池余量。
- 压测数据为合成用户，未使用真实用户资料、订单或支付材料。
