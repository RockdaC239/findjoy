## 0. v2 修订摘要（先读）

1. 用真实存档确认了 2.2 的检测表格，并发现更严重的问题：12 局里 8 局 `extractLifeStorylines` 返回 `[]`，跨局职业防重对多数人生根本没有生效；退休后当前职业变为"退休"，历史职业也基本丢失。
2. 确认 2.5 的真实越权路径：a17ec 第 18 岁那一幕把 `objectiveChanges.education` 从"初中在读"直接写成"中职在读，机电技术应用专业"，`lifeChanges=[]`。中职/技校/中专/高中都不在 `educationPath` 里，所以完全没被拦。
3. 原 §7 的验收门槛"至少一半首个选择不是接活/入职/接店/选职业"用现状就能通过（11 局真实开局里只有 4 局首个选择是接活/打工），而最典型的撞车局（a17ec）首个选择是"鱼缸卖不卖"，反而能过。该门槛改为辅助指标，主指标改为开局机制分布。
4. 补充 2.6 与实施约束：`buildBirthDirective` 是每轮都注入的，新开局方向只能挂在 `isOpening || openingRecoveryAge` 那一轮；`OPENING_SCENES` 是出生地＋父母职业 id 的哈希，不是随机、也不看最近几局，它只是空间提示，不能承担多样性。
5. Mock 排除不能只看当前 `flags.developerMock`：真实续玩会把 `developerMock` 覆写为 `false`（`app/api/life/[id]/next/route.ts`），Mock 开局＋真实续玩的局会被当成真实样本。开局方向在 Mock 下不抽样即可。
6. §7 首组 20 个样本必须同一用户、按顺序生成，否则近期防重不触发，等于白测。
7. 地点软避让需要实施时先复现确认：近 12 局 4 局上海，其中 3 局落在最近 5 局内；当前 0.25 软权重下单局约 2.5%，连环出现概率极低。若这条链路实际没生效，§4C 的"根据最近几局降低相似概率"要一并修。

## 2. 问题与已验证证据

### 2.1 出身确实不同，成长故事仍在重复

实际本地体验中，父母职业已经从设计、物流、企业经营变化到家政、医疗服务、银行等领域，但开局仍反复汇入：

> 儿童接触一门手艺 → 大人发现孩子手巧/坐得住 → 赠送旧工具或旧物 → 十五岁面临接活、学手艺或保留物件的选择 → 后续进入相关职业。

另有一类反复出现的结构：父母摊出志愿/岗位安排，玩家在听从、拒绝、折中之间选择。换掉职业和道具，并没有改变玩家面对的问题。

本文只保留匿名机制摘要，不把玩家完整存档、原始提示词、账号信息或 ForU 自述复制到 Git。

### 2.2 职业防重复存在可直接复现的盲区

检查 `lib/storyline.ts` 的现有函数，以下为修复前实际结果：

| 输入 | `detectStorylineDomains` 结果 | 问题 |
| --- | --- | --- |
| 汽修厂技师 | `[]` | 漏掉维修技工 |
| 机械维修工 | `[]` | 漏掉生产维修 |
| 建筑绘图员 | `[]` | 漏掉建筑设计 |
| 规划院助理规划师 | `[]` | 漏掉城乡规划 |
| 老师问你去不去云南调研 | `["education"]` | 把他人称谓当成主角职业线索 |
| 软件工程师 | `["tech"]` | 已有正常识别的对照 |

实际主角从事规划的存档被概括成“教育”，汽修人生主要被概括成“创业”。下一局只避开这些标签，自然没有避开维修、机械和师傅带徒弟。

注意：不能简单删除所有“老师”匹配；主角本人的教师职业仍需要正确识别。关键是区分职业事实、他人称谓、尚未选择的机会和普通兴趣。

**v2 实测补充（本地最近 12 局真实存档，均为真实模型生成）：**

| 观察 | 结果 |
| --- | --- |
| `extractLifeStorylines` 为 `[]` 的人生 | 12 局中 8 局 |
| 从事规划的存档 | 当前职业“规划院助理规划师”→`[]`；只因一条 career 标题里有“老师”才得到 `education` |
| 汽修人生（81 岁，已退休） | 当前职业“退休”→`[]`；只因标题出现“汽修厂老板”命中“老板”才得到 `startup` |
| 完整复刻“发现手巧＋赠旧工具＋师傅/接活” | 12 局中 3 局，而最近一局（11-07，18 岁）就是 |

结论：跨局职业防重此前对多数人生是空转。修准检测是必要的，但它只解决“该避开什么”，不解决“开局怎么写”，所以 §4C 才是主修复面。

### 2.3 当前跨局防重没有记住开局机制

现有流程大致是：

```text
start API
  → recentBackgroundAvoid：近期省份、父母职业 ID、家庭背景
  → recentStorylines：近期主角职业领域
  → resolveStartPlan / createStartLife
  → prepareEventRequest / buildSystemPrompt
```

它没有明确记录“又是被师傅发现特长”“又收到旧工具”“又让十五岁孩子接活”等跨局体验特征。`buildRecentSituationHint` 主要看本局近期事件，不能替代跨局开局防重。

### 2.4 场景选择与开篇结构不足以产生差异

- `lib/birth/profile.ts` 用出生地点与父母职业 ID 的哈希，选择一类 `OPENING_SCENES`。
- `birth.json` 的分类主要是家庭、邻里、学校、市场等空间；不同空间都能写成“遇到师傅、显露手艺”。
- `opening.md` 对第几段写什么规定得较细，鼓励同一关系反复出现并在十五岁兑现，模型容易套固定成长骨架。
- 连续性规则又鼓励旧人、旧物、旧经历回响，容易把最初的工具或兴趣固定为一生的职业方向。

采样器在变化父母职业、地点等信息；目前没有证据证明随机数被固定。模型温度是次要待验证因素，不应先以提高温度或换模型替代上述修复。

**v2 实读代码后必须补的三条：**

1. `OPENING_SCENES` 是“出生地＋父母职业 id”的确定性哈希，同一组出身永远得到同一个空间提示，且**不看最近几局**。它只能当空间背景，不能承担多样性；新的开局方向必须独立抽样。
2. `buildBirthDirective(birth)` 在 `buildSystemPrompt` 里对**每一轮**都追加，不只开局（`lib/engine/prompts/assemble.ts`）。新的开局方向若挂在那里，会一路污染成年剧情。必须只在 `isOpening || openingRecoveryAge` 的普通模式轮次注入。
3. `craft.md` 里“旧物/旧话回来要有新意思”写的是“当年学过的手艺，成了你拒绝一份工作的底气”，不是强制职业化，**不算元凶**，不要顺手扩大改动范围。真正把旧物绑成第一个选择的是 `opening.md` 的“第四段必须留未完成 + story 接着它”。

### 2.5 选择边界仍漏掉中职等路径

已有新协议检查了部分高等教育和正式职业承诺，但 `educationPath` 的覆盖不完整。实际体验存在“只处理童年物件，下一幕却进入中职机电和车间”的情况。

中考成绩可以自然发生；选择普高、中职、技校、学徒、专业或进入工作，不能仅由童年兴趣替玩家决定。也不要把普通义务教育升年级误判成必须新增授权。

**v2 真实失败样本（可直接做回归 fixture）：**

```text
第 15 岁：选择"让收废品的搬走，把两百块收下，螺丝刀留着"（与升学无关）
第 18 岁：objectiveChanges.education = "中职在读，机电技术应用专业"，lifeChanges = []
         → 未被拦截，因为 educationPath("中职在读…") = undefined
```

同一份存档里，`career.occupation` 一直是"学生"，职业校验放行；`education` 才是被越权改写的字段。所以本轮修复必须落在 education 的**层级变化**上，而不是只加职业正则。

### 2.6 原验收门槛有一个会骗人的指标

原文 §7 写“至少一半首个选择不是直接接活、入职、接店或选职业”。本地 11 局有首个选择的真实开局里，只有 4 局的首个选择是接活/打工（36%），这个门槛**现状就能过**。

但最典型的撞车局 a17ec：首个选择是“鱼缸卖不卖”，完全通过门槛；它的问题在下一幕直接落到中职车间和老师傅。也就是说，该指标测的是“动词”，不是“机制”。

v2 改为：

- 主指标：开局机制分布（见 §7 表）。
- 辅指标：首个选择里“接活/入职/学徒/打工”不超过一半；同时抽检“首个选择是否与本局抽中的开局方向一致”。

## 3. 修复目标与非目标

本轮必须完成：

- 修准主角职业/教育路径识别，修掉漏识别和他人称谓误识别。
- 让新局参考近期真实体验中的开局机制，避免只换名词。
- 在现有出生采样与人生状态中加入轻量、稳定的开局创作方向。
- 放松固定段落结构，解除童年兴趣、旧物与成年职业的自动绑定。
- 补齐中职、技校、学徒及其他重要去向的选择边界。
- 用跨局样本和后续展开验证，不以单局文字好看或标签均匀代替验收。

不做：新增独立人生引擎、独立数据库/向量库、完整人生预排、固定职业分配、用户分数、新 UI 或依赖。默认不为每轮增加一次模型审查/分类调用，不通过穷举关键词拒绝整篇故事来制造重试。

## 4. 推荐实现

### A. 区分职业事实与叙事提及

优先复用并调整 `lib/storyline.ts`：

- 补上建筑/规划、生产制造、维修技工等实际缺失领域，具体合并粒度按现有目录确定，不无限扩职业标签。
- 主角当前职业、已成立的职业变化是主要证据；明确的专业路径可作辅助。
- “大学在读”不等于教育行业；“老师邀请你”“父亲在银行”“邻居是护士”不等于主角从事这些职业。
- 尚未接受的岗位不能先算作已发生的职业；业余兴趣也不能直接当职业。
- 父母职业去重与主角职业去重分别处理。

不要只扩大正则词表。需要同时检查 `careerMarkers`、`extractLifeStorylines` 及它们的调用方，避免继续从单个标题中的他人身份推断主角职业。

**v2 落地规则（必须按此实现，否则真实数据仍会误判）：**

- 证据分两级：**一级**是 `state.career.occupation` 与每次 `objectiveChanges.occupation`（已成立的职业事实）；**二级**只用于“当前职业是退休/学生/待业这类无信息身份”时回看历史职业事实。
- **事件标题不再参与职业域判定**。标题只描述处境（“老师问你去不去云南调研”“父亲让你暑假去工地画图”），不证明主角从事该职业。现有 `careerMarkers` 同时取 title 和 occupation 是 28e93 被误判成 `education` 的直接原因。
- 新增领域建议（按现有风格合并，不要无限拆）：
  - `construction` 建筑规划：建筑、规划、测绘、土木、施工、设计院、绘图、造价（注意不要匹配“图书馆”“图纸”这类无关词）。
  - `manufacturing` 生产制造：制造、车间、机床、加工、工艺、机械、机电、电工、焊接、装配、质检、产线。
  - `repair` 维修技工：维修、修理、汽修、修车、机修、钳工、技师、学徒工、4S。
- `service` 里的“技师/师傅”不要删，但要确保“汽修厂技师”优先命中 `repair`，避免只落到 `startup`（“老板”）或 `service`。
- `extractLifeStorylines` 现在返回空会让跨局防重空转：允许“只有历史职业事实、当前已退休/学生”的人生仍提取出历史主线，但**不要**把童年标题里的“修车摊”“竹编”算成职业。

### B. 增加少量开局特征，复用现有存储

为新开局保留最小必要的内部元数据，围绕以下四类信息（代价类型是 v2 实测后追加的）：

| 维度 | 示例含义（非固定故事） |
| --- | --- |
| 主要关系 | 照护者、同龄朋友、邻里、已存在的兄弟姐妹等 |
| 推动力 | 自己的愿望、共同活动、环境变化、关系变化、家庭安排等 |
| 故事机制 | 守住秘密、共同完成、被误解、争取机会、探索陌生生活、发现特长等 |
| 代价类型 | 人情、时间与机会、站边、面子、承诺、失去与告别、信任、钱与开销（降权） |

代价类型是 v2 实测后加的第四维：模型需要一个“具体的代价”才写得动选择，而它默认抓的是钱。把钱降到普通一项、并让“代价类型=人情/时间/站边”的局不许出现工资，才能既保留张力又不让十五岁变成打工年龄。

可以使用 `LifeState` 的可选 `openingPlan` 等元数据；字段名与组织方式在读完现有类型后确定。创作描述与模板放在 `lib/engine/prompts/` 的 JSON/Markdown，TS 只负责枚举、采样、校验与组装。不把创作指令正文堆进 TS。

要求：

- 服务端抽样，随本次开局状态保存；刷新、模型重试、恢复存档不得重新抽。
- 复用已有开局幂等流程；不要把随机计划加进会使同一幂等 key 改变的请求哈希。
- 新字段可缺省，旧存档正常读取，不批量回写历史；未知特征就是未知，不能默认成手艺路线。
- 读取近期特征必须按当前用户过滤。开发 Mock、没有成功生成开局的空壳不作为真实体验样本；真实未玩完的开局仍应计入。
- 不把旧局全文或 ForU 自述带入新局；传递少量必要标签/摘要即可。
- 老存档允许有限的只读兼容提取，无法可靠判断就跳过；不得为补标签新增整库模型调用。

**v2 落地规则：**

- 计划只存**目录 id**（`relationship` / `driver` / `mechanism`），不存模型自由文本；读取时按目录重新取标签，未知 id 直接跳过。这样旧目录或损坏字段不会进入提示词。
- 抽样时把“最近用过哪些 id”一并算好写进计划（少量字符串），因为开局提示词在 `streamNextEvent(state)` 里组装，**拿不到路由层的近期查询结果**；不写进去就无法在提示词里说“最近几局用过什么”。
- Mock 开局**不抽样、不写计划**。当前 Mock 续玩会把 `flags.developerMock` 改写成 `false`，所以“看当前 flags”不足以排除 Mock 样本；不写计划是最省事且不会污染的办法。
- 近期查询用 `updated_at` 取最近 6 局、跳过 `flags.developerMock === true` 与没有计划的局；不去回读全文，也不做关键词提取。

### C. 先采样处境，再生成故事

在现有 `resolveStartPlan / createStartLife` 流程附近选择开局方向；根据最近几局，降低相似组合的概率。

- 方向是创作约束，不是预写剧情，更不是成年职业。
- 同一份出身应能写出不同的生活切面；同一机制也可有不同人物与情绪。
- “被发现特长”“旧物赠予”“师傅带徒弟”仍可出现，但不能长期占据默认路线。
- 开局不必靠工作机会或经济困境推动；友情、好奇、归属、一次共同活动也能形成重要选择。
- 计划必须符合出生事实。例如档案没有兄弟姐妹，不能为了匹配计划临时添加；父母缺席不能凭空写成日常陪伴。
- 参考近期体验，但不能因为职业防重而拒绝玩家后来明确选择的职业。

新增策略优先作用于普通模式。主题模式保留主题意图，不因“防重”把事业主题拉成无关人生；剧本与 ForU 不注入随机童年或覆盖原情境。共享开篇文案的变更也要验证主题模式。

**v2 落地规则：**

- 采样放在 `resolveStartPlan`（普通模式）里，随 `StartPlan` 交给 `createStartLife` 写进 `state.openingPlan`；重试、刷新、恢复都复用同一份状态。
- 目录里把“发现特长/手艺传承”当成**普通一项**并降权，不能是默认项；“家庭安排”同样降权。其余机制权重相当。
- 近期同一 id 权重降到 0.15 左右；抽中的三元组与最近几局完全相同时重抽（有限次），仍相同则接受。不要近期的硬排除，否则少数派会被压成单值。
- 注入位置：`buildSystemPrompt` 里新增一段，只在 `scenario.mode === "normal" && (isOpening || openingRecoveryAge !== undefined)` 时追加；不要在 `buildBirthDirective` 里加，也不要进入之后任何一轮。
- 注入内容只描述“本局处境方向”，并明确：不是预写剧情、必须符合出生事实、十五岁不必是工作机会、若方向不是手艺/传承就不要写师傅与旧工具。
- 代价类型与机制一起进提示词；代价不是“钱与开销”时，明确不写“给你多少钱/做一天多少钱/一个月多少”。
- `OPENING_SCENES` 保留原样作为空间背景；它不承担多样性，也不需要改哈希。

### D. 重写开篇目标，松开段落模板

保留：出身可理解、关系具体、童年有生活、十五岁有牵挂、可以继续选择。

取消或弱化：固定第一段/第二段/第三段各做什么、必须让同一关系重复出现、必须埋一件贯穿一生的物品、必须展示职业型特长。

明确：

- 旧物可以只是旧物，兴趣可以改变，童年关系可以淡出。
- 承接既有经历是记住它，不是必须把它发展成职业。
- 不强制每局最终汇入“志愿、兼职、接店、入职”这条序列。
- 题材与情绪允许温暖、好笑、尴尬、冒险、亲近、失落；不依靠灾难和重病制造差异。
- 单局自己的文风应连贯，但不同人生可以有不同的叙事重心。

遵守提示词分层：主要改 `opening.md`，只在确有通用冲突时调整 `craft.md` / `two-scene.md`。不要继续叠加互相矛盾的要求，也不要把本地某一局的人物、城市、道具、金额原样写成通用示例。

**v2 落地规则：**

- 必须显式写“不要每局都落到‘大人发现手巧 → 送旧工具 → 学手艺/接活’”，把它作为**反面样例**，而不是继续正面描写“五到十岁的手艺场面”。
- 十五岁的第一个选择不必须是工作机会；但也不能退化成纯情绪描写，仍要有一个具体、可答复的处境。
- 保留“story 接住 narration 最后的未完成”，否则第一个选择会散掉；只取消“四段各写什么”的硬模板。
- 篇幅、事实边界、`{{...}}` 占位符规则保持不动。

**v2 第一轮真实样本暴露的两条追加规则（必须保留）：**

- 只写“不要把师傅/旧工具当骨架”不够，模型仍会用“拆装、修东西、你手稳”当孩子的定义性特长。必须点名：
  - 不写“你手稳/你手巧/坐得住”；
  - 不把拆装、修理、旧零件、工具袋写成孩子的特长或第一个选择的由来；
  - 父母的职业不要自动变成孩子的天赋或未来职业。
- 只写“不必是工作机会”也不够，模型仍会让十五岁孩子“摆摊拿两成 / 去店里看店 / 帮工到年底”。必须写成：
  - 不写工钱、分成、一个月多少、管吃住给零花；
  - 帮忙的代价是人情、时间、机会或一句难说的话，不是一笔工资；
  - 即使方向是家庭生意，第一个选择也不要是“去不去打工”。
- 第一个选择的三个选项必须是三种行动方向，不能是“接受/拒绝/先试试/再商量”的同一件事，也不能是同一件事的三种程度。

### E. 补全教育与职业选择边界

复用当前 `commitments / lifeChanges` 和事实校验，不另起一套权限协议。

重点区分：

- 正常升年级/沿已选路径毕业：可以过渡。
- 选择普高还是中职、学校/专业、学徒还是升学、正式就业或长期留任：需要明确的玩家选择。
- 中考落榜是处境，不自动授权机电中职或某个师傅。
- 短期参观、帮忙、接触工具不等于同意学徒或就业。
- 有明确多年期限的学习/工作不应因为“先试试”被机械锁死在同龄；保持已有短期跟进与多年推进规则相容。

避免“改一个词就误判所有毕业/职业进步”的粗粒度检查；保留上一轮已有婚恋、生育、住房、终幕与数值回归。

**v2 落地规则（按教育层级，而不是按关键词白名单）：**

把 `educationPath` 换成“教育阶段序号”：

| 阶段 | 关键词 | 是否属于“选择点” |
| --- | --- | --- |
| 0 未开始 | 未开始、未填写、已成年 | 否（未知就跳过） |
| 1 学前 | 幼儿园、学前 | 否 |
| 2 小学 | 小学 | 否（义务教育） |
| 3 初中 | 初中 | 否（义务教育） |
| 4 高中 | 高中、普高 | 常规延续（小学直接跳高中才拦） |
| 5 中职 | 中职、中专、技校、职高 | **是** |
| 6 专科 | 专科、大专、高职 | **是** |
| 7 本科 | 本科、大学在读、大学生 | **是** |
| 8 硕士 | 硕士、研究生 | **是** |
| 9 博士 | 博士 | **是** |

拦截条件：新阶段是分流点（中职/技校、专科、本科、硕士、博士），且（旧阶段已知且新阶段 > 旧阶段），且 `lifeChanges` 不含 `education` → 拒绝并提示先把升学机会交给玩家选。旧阶段无法识别（如“已成年”“未填写”）时跳过，不猜。

初中→中职、高中→本科、本科→硕士 会被拦；高一→高二、高三→高中毕业、本科→本科毕业、大学在读→毕业 不会被拦。义务教育内部升年级不拦。

**普通高中单独放行（v2 实测后调整）**：把“初中→高中”也当成必须授权，会让模型在 15→18 的跨年里连续三次被拒，最后写出“18 岁初中在读、下一幕却 22 岁高中在读”的坏时间线，比不拦更糟。普通高中是义务教育后的常规延续，不构成“分流”；真正要拦的是中职/技校/专科这条把童年兴趣直接兑换成职业的通道。因此：初中→高中放行，小学直接跳高中仍然拦。

真实回归样本直接用 §2.5 的 a17ec：`education: "初中在读"` → `"中职在读，机电技术应用专业"`，`lifeChanges: []` 必须被拒；补上 `lifeChanges: ["education"]` 后必须通过。

## 7. 真实模型验收

只使用合成资料；使用项目当前真实生成/规范化入口，不绕开校验写一套演示脚本。原始样本放 Git 忽略的 `.data/`，提交匿名汇总。

### 第一组：不同出身，约20个普通开局

逐个阅读并记录：家庭事实、选中的开局方向、实际主要关系/推动力/机制、首个选择、是否预定成年职业、是否与近期样本实质重复。

**生成方式（v2 必须先定）：**

- 必须**同一用户、按时间顺序**生成，每局都把前几局当作近期样本传进去，才能验证防重真的触发。用固定种子、单进程顺序跑，间隔调用避免限流。
- 脚本要复用 `resolveStartPlan`（含近期方向与背景避让）、`createStartLife`、`streamNextEvent`、`applyNextEvent` 和现有规范化/校验，不要自己拼提示词。
- 原始输出写 `.data/opening-diversity-*`；每局的“抽中方向”和“实际写出来的机制”分别记录，两者不一致本身就是要观察的失败。

建议首轮验收门槛（用于审阅，不硬编码成游戏配额）：

| 指标 | 门槛 |
| --- | --- |
| 能辨认的实际故事机制 | ≥ 6 种 |
| 能辨认的主要关系 | ≥ 4 种 |
| 能辨认的推动力 | ≥ 3 种 |
| 能辨认的代价类型 | ≥ 3 种 |
| 十五岁出现带报酬的活（工钱/分成/零花/看摊给钱） | ≤ 2/20 |
| “大人发现手巧＋赠旧工具＋接活/学徒”完整组合 | ≤ 2/20 |
| 首个选择是接活/入职/学徒/打工 | ≤ 10/20（辅助指标，不单独判定通过） |
| 抽中方向与实际开局基本一致 | ≥ 15/20 |
| 同一机制重复出现（含换地点换人物） | 同一机制 ≤ 4 次 |

不能通过给相同故事贴不同标签达标，也不能靠增添创伤、死亡、超现实反转充数。

这是小样本编辑验收，不是统计显著性结论。达不到先分析原因，不隐藏失败样本或通过重抽只保留好结果。

### 第二组：同一出身，至少4个不同开局方向

固定出身事实，只改变合法开局方向。检查不是换一个地点仍演同一件事；也不能为了差异改父母职业、家境和亲属结构。

### 第三组：至少3条后续轨迹

从不同机制的开局各继续6～10次选择，观察是否又汇入同一套“手艺→职校→师傅→接店”或“父母安排→志愿→兼职”。验证童年兴趣可以保留、淡出或改变，职业由后续机会和玩家选择形成，而不是开局暗中预定。

同时验证主题、剧本、ForU和旧存档兼容。不要声称几幕续玩就证明所有模式完整一生都合格。

记录模型、样本数量、调用/重试、延迟与可用usage。连续失败或人工重试必须记录；没有有效计价时不把estimatedCostUsd=0称为免费。不要上传玩家原始存档或ForU自述做实验。
