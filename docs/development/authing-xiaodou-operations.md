# Authing 与小豆支付运行说明

## 当前边界

2026-11-03 定价版本（本地 `test` 分支，未发布）：充值入口统一为「积分充值」。普通模式单次购买 ¥5.9/20 积分；四档为尝鲜包 ¥9.9/40 积分、标准包 ¥19.9/100 积分（主推）、探索包 ¥39.9/220 积分、深度包 ¥79.9/480 积分；普通模式每局 20 积分，剧本模式暂保持原权益折算后的每局 20 积分，主题与 ForU 不开放。新用户默认一次性赠送 40 积分，已有用户不重复领取。

首次访问积分业务时，SQLite 原子执行一次 `points-v1` 转换：旧余额、预占、账本和历史订单权益按 1 次＝20 积分折算，支付金额、请求体、支付编号保持不变。开局按操作快照记录预占积分，成功消费、失败和过期按原预占积分释放。回滚代码前必须核对积分单位，不得让旧版按次数消费转换后的积分数据库。本地转换前备份位于忽略的 `.data/life-before-points-20261102.db`。后面的次数测试记录是历史口径。


2026-11-02 起付款页面仅提供微信支付。新订单接口拒绝支付宝，历史支付宝订单禁止重新获取支付链接，但保留查询、已付款确认及原有流水。恢复支付宝须先验证通道，再同步调整页面、新建与重拉起接口。

已实现统一用户映射、登录会话、用户存档隔离、次数账本、生成幂等、小豆签名/验签与订单页面。默认使用演示商品：不向小豆下单、不真实扣款、不发放真实付费次数。Authing 登录是真实认证，不提供线上绕过登录的演示后门。

首次注册默认赠送 40 积分，`FINDJOY_TRIAL_CREDITS=0` 可关闭。赠送按用户只记一次，修改配置不会重复赠送；定价和免费额度仍可在正式运营前调整。

## 本地配置

复制 `.env.example` 中必要项到忽略的 `.env.local`，不要覆盖已有模型配置。

- `FINDJOY_APP_ORIGIN`：本地 `http://localhost:3000`，生产为真实 HTTPS origin，不带 `/findjoy`。
- `AUTHING_ISSUER`：从应用配置复制 `/oidc` issuer。
- `AUTHING_CLIENT_ID`：应用 ID。当前已复用原示例应用并改名 FindJoy 觅乐。
- 当前协议为授权码 + PKCE、RS256、公有客户端 `token_endpoint_auth_method=none`，不需要 App Secret。若改成机密客户端，配置 `AUTHING_CLIENT_SECRET`，并把平台 token 验证方式设为 `client_secret_post`。
- 回调固定为 `<origin>/findjoy/api/auth/callback`，必须在 Authing 精确登记，不使用通配符。已登记 localhost:3000 与生产域路径；生产部署前仍需验证实际可达。
- 自有登录入口 `/findjoy/login` → 标准 Authing 验证页。不要自行校验或保存验证码。
- 面向消费者的应用须在「访问授权 → 应用访问控制」把默认「所有人」设为「允许」；这只允许认证用户进入应用，付费权益仍由 FindJoy 校验。若验证码通过后提示「无权限登录此应用」，先检查此规则。2026-11-01 已修正默认拒绝规则并验证持久化。
- 会话令牌只在 HttpOnly Cookie，数据库存哈希；本产品退出撤销本地会话，尚未实现身份平台的全局退出/封禁事件联动。

账号映射暂随 FindJoy 部署。FindFire 接入前须把全局映射暴露为公共身份能力，不能在 FindFire 各自生成另一份 UUID。FindFire 的现有 `rocc` 和 UUIDv5 映射须按关联文档迁移。

## 小豆真实收款启用前

1. 确认正式价格、体验范围、fallback 是否收费及退款权益回收规则。当前首幕生成即消费（包括模型的规则降级）；用户主动重复开局会消费新的次数。
2. 在服务器持久化目录保存商户 RSA 私钥（权限 600），只向平台上传公钥，并完成持有证明与短信二次验证。本地密钥位于忽略的 `.data/`；2026-11-01 已核对门户商户公钥为 ACTIVE，指纹与本地公钥一致。服务器私钥部署与实际签名收款仍待验证。
3. `XIAODOU_BASE_URL`、`APP_ID` 从门户复制；`KEY_ID` 使用上传公钥后显示的商户 mkid，不是平台 kid。
4. 把官方发布的平台 PEM 以 `{ "平台kid": "PEM正文" }` JSON 保存到 `XIAODOU_PLATFORM_KEYS_FILE`，核对文档与门户的 SHA-256 指纹。轮换时允许新旧 key 并存。
5. 维护真实服务器出口 IP 白名单，不关闭来源校验。nginx 必须覆盖 X-Real-IP；应用只监听回环地址，不信任公网客户端自报 IP。
6. 在小豆登记虚拟商品交易形态 `CARD_VIRTUAL` 和申报域名；确认相应支付通道已放行。
7. 应用配置的 notifyUrl 指向 `https://<域名>/findjoy/api/payments/webhook`，必须公网可达且无 query/fragment。未配置时平台不生成事件，之后不会补回历史事件。
8. 确认平台实际收银页的 HTTPS origin，填写 `XIAODOU_CASHIER_ORIGINS`，不要猜地址。支付材料只给订单所有者，不放日志、埋点和第三方二维码服务。
9. 录入 `FINDJOY_PRODUCTS_JSON`，每项包含 `id,name,credits,amountFen`，金额为整数分；最后再设 `FINDJOY_PAYMENTS_MODE=live`。正式模式缺少商品会拒绝工作，不会沿用演示价。此次发布须将 GitHub Actions 的 `APP_ENV` 中 `FINDJOY_PRODUCTS_JSON` 替换为 `.env.example` 的五个商品（含可下单的 single），并将 `FINDJOY_TRIAL_CREDITS` 设为 40；旧环境值会覆盖代码默认值，不能仅修改页面。不得修改历史订单或追回已有赠送。
10. 平台无沙箱。进行受控首单：下单、真实付款、验签通知、次数到账、重复通知只入账一次、断网恢复、查单补偿。未真实验证前不能宣称支付可上线。

支付回跳仅作导航，到账只依据验签通知或验签后的查单。`UNKNOWN` 保持待确认，不换单号重下单。订单页可重试获取支付材料，同一次请求重用 requestId/body，nonce 换新；平台要求新尝试时按同一业务订单调用 attempts。

## 对账与异常恢复

- 用户订单页查询会主动查单并幂等补发次数，同单 4.5 秒内复用本地快照；接口另有用户级限流。
- 可配置至少 32 个随机字符的 `FINDJOY_RECONCILE_TOKEN`，由可信调度器每 5 分钟 POST `/findjoy/api/internal/reconcile`，Authorization 为 Bearer token。不把 token 放 URL、Git 或公开命令输出。
- 每批最多处理 10 笔、覆盖最近 30 天的未成功真实订单，优先最久未查询的记录。返回 checked/unconfirmed 计数；unconfirmed 非零应排查配置/网络，长期 UNKNOWN 联系平台核对。更老订单走人工核查。
- 过期开局预占在下一次开局、账户查询、套餐页和对账调用时释放；旧生成任务通过租约被阻止写入。未单独部署任务队列。
- 生成超时或断流：保留相同开局请求键，查询原操作或恢复已保存人生；不要自行补扣。
- 退款规则尚未确定，暂不提供自助退款。`REFUND_*` 等财务事件现在会进入 `joy_payment_review_events` 待复核队列，返回成功停止平台重试，但不会自动改订单或积分；需按[退款与积分调整流程](payment-refund-adjustment.md)人工处理。不要在平台后台直接退款后忽略本地次数。
- 当前退款处理是启用真实商业化前的限制，不应以模拟订单测试代替此项。

## 数据库与发布

沿用 `LIFE_DB_PATH`，WAL + synchronous=FULL。新增表/用户归属采用增量创建，旧存档保留但不会开放给任意新账号认领。发布前备份数据库，验证能恢复；在线 SQLite 使用 backup API，不只复制主 db 文件而遗漏 WAL。

身份、次数、订单、生成状态位于同一 SQLite 文件以保持本地事务。状态和 transcript 同事务保存；订单确认、事件去重与次数发放同事务完成。将来多实例再迁移托管关系数据库，不提前改造现有部署。

保留私钥、平台公钥文件、数据库及环境变量在源码发布目录之外；当前部署不会自动同步本地 `.data` 或 `.env.local`。数据库结构不能依靠回滚代码撤销，回滚前先核对兼容性。
