# 续局节奏与讲述调整（2026-11-07）

## 改动

沿用 v3 的 narration → story 两幕与 0～8 年（剧本/ForU 0～5 年）协议，不迁移旧存档，不增加控制器或模型调用。普通、主题开篇仍落到 15 岁；剧本和 ForU 保留自己的开局年龄和情境。

- 稳定生活通常跨 2～5 年，近期结果在讲述开头兑现，再向下一处重要变化过渡；同龄承接留给重要转折，不为日常手续反复出题。
- 请求提供最近四幕的年龄、间隔和题材。首个可见节点没有前驱时跨度为 null，不把剧本的起始年龄当作跨过的年份。
- 短期讲述约 200～350 字，跨数年约 350～550 字；童年开篇维持独立篇幅。篇幅是写作指导，不增加按字数拒绝输出的重试。
- 通过投入、期待、具体相处与回响积累情绪，允许舒缓与收获；决策的强取舍要求不再套给每段过渡。避免把电影感等同于不断制造灾难或期限冲突。
- 支持 companyType、careerStage 新值的解析和保存，提醒毕业/就业同步状态；现金、资产、债务保留净增量规则。缺失记忆时允许依据真实历史补建活跃人物，不虚构前史。

## 真实模型验证

使用本地配置的 deepseek-flash，通过现有请求组装、规范化与状态应用流程生成。仅使用合成资料，没有发送玩家存档，没有写入业务库或扣玩家积分。样本保存在 Git 忽略的 `.data/narrative-pace-check*` 目录。

同一合成选择点的首轮对照：旧提示词讲述 128 个字符、跨度 1 年；第一版调整后 344 个字符、跨度 0 年。此对照只用于定位趋势，不是统计实验；模型采样、示例与请求字段不同，不支持归因到某一句提示词。

第一版连续六轮停在 19 岁，说明只允许同龄承接会放大琐事。第二版六轮跨度为 0、1、1、1、1、2，仍过细。进一步明确“先交代近期结果，再讲过稳定生活，跨度由下一个重要处境决定”后，第三版六轮跨度为 2、2、3、2、1、1，从 19 岁走到 30 岁，讲述字符数分别为 375、303、384、378、388、395。人物记忆从第三轮以内开始建立，借款、旧物和朋友的约定有跨轮回响。验证后又补充了 story 必须落在当前年龄的明确说明。

## 限制

真实样本仍有局部金额、年级与场景时序不一致，也有任务型取舍重复；结构校验不能证明语义正确。当前改动改善生成指导，不保证每轮都符合建议跨度、字数或情绪效果。需要 Owner 连续试玩验收，不能把六轮样本当作整个人生或所有模式的质量保证。旧存档已发生的金额、年龄和事件均不自动修复。

Markdown 在模块初始化时读取，现有开发服务需重启才会确定加载最新写作指令；生产发布仍须另行授权。
