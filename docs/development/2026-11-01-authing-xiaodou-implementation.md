# FindJoy 登录与支付实施计划

状态：实施中。供应商由 owner 指定：Authing、小豆支付。套餐价格仅演示，不作为真实收费依据。

## 范围与架构

保留 Next.js + SQLite，统一身份映射与 FindJoy 权益分别存储；FindFire 未来复用同一 Authing 用户池与全局身份契约，不共享人生和会员余额。

登录使用 OIDC 授权码 + PKCE、state/nonce、安全 Cookie 与服务端会话；自有登录页承载品牌说明和进入认证的入口，不自建密码或验证码校验系统。所有人生接口校验用户归属；旧匿名数据隔离。

支付使用小豆 RSA2 开放接口，验证请求/响应/原始 webhook 签名。订单、去重、余额与次数流水使用 SQLite 事务。价格未定，演示套餐只能模拟付款，不向真实渠道下单；演示权益与真实支付明确区分。真实通道需显式服务端配置正式商品后开启。

## 设计规格

沿用 globals.css 的纸白 #f8f8f6、墨黑 #11110f、橙色 #ff5a1f、现有字体与圆角。登录页采用品牌故事 + 登录卡片；套餐页展示三张克制的体验卡；支付页展示订单摘要、渠道选择、状态与返回入口。手机单列、触控目标至少 44px；错误就地可见，不隐藏必要导航。

## 资料与当前发现

小豆资料版本 1.0.0，下载资料在忽略目录 .data/，不提交账户配置或密钥。平台无沙箱，真实首单不能用模拟测试替代；未配置 notifyUrl 时不会补发历史事件；接入需要应用、公钥、出口 IP 白名单、申报域名与可达 HTTPS 回调。公开订单必须使用虚拟商品申报形态 CARD_VIRTUAL。

Authing 控制台已有一个示例 Web 应用，免费档应用额度已满；优先核对现有应用配置，不自动购买升级。短信或邮箱发送受额度与认证条件约束，不为测试擅自发送短信。

## 非目标与交付边界

不建设通用计费平台、不部署 FindFire 认证改造、不迁移无法证明归属的旧数据、不发布演示价格到真实收款。完整应用配置、回调公网可达和真实首单需实际验证，缺失时明确记录为未完成。
