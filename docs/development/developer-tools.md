# 个人开发调试工具

2026-11-03 更新：按 Owner 反馈改为原页面内的调试模式，撤掉独立节点预览页和占用文流的工具横条。未发布。

## 进入、打开遥控器与退出

- 首页左上 Logo 连续点击三次（相邻点击小于800ms），服务端核验当前会话账号的已验证手机号后，弹窗选择「进入调试模式」或 Showcase。
- 进入后仍在原页面；左上角常驻 `dev` 三角角标，Logo 右侧出现 Debug 图标。游戏页没有 Logo，图标放在顶部操作区。
- 点击 Debug 图标才打开悬浮「调试遥控器」。优先在当前点击图标下方8px展开，下方不足时翻到上方，视口边缘留16px；滚动、缩放及内容尺寸变化时重新定位，图标滚出视口则收起。使用 fixed 定位，不占文流，不添加遮罩，不阻断产品操作；可以点击收起或按 Esc，焦点回到打开按钮。收起不退出调试模式。
- 退出只放在首页三连点弹窗的「退出调试模式」中，退出同时关闭 Mock、隐藏角标和图标。`/developer` 旧地址仅重定向首页。
- 原弹窗三个操作已统一高度、宽度、字体与圆角，链接不再带下划线。

## 权限与持久化

`lib/developer.ts` 从当前会话用户读取 `identity_users.phone`，只接受现有 OIDC 已验证手机号写入的数据。兼容国内号码及 +86/0086 前缀，不从昵称、前端布尔值、localStorage 或请求手机号认定身份。

调试与 Mock 偏好通过同源、鉴权的 `POST /api/developer` 写入 HTTP-only Cookie，刷新/跨页保留。Cookie 只表达偏好，不代表权限；start/next/ending 在读取 Mock 偏好时仍核验手机号。普通用户伪造 Cookie 会被拒绝，不能获取免费开局或模拟结果。

## 三步 Mock 普通模式

进入调试默认不开 Mock。遥控器内开启「普通模式 Mock」后，从原首页开始普通模式，经过原有性别选择与真实游戏页面：

1. 开局：8岁童年，无选项，点击「继续」。
2. 正常体验：32岁事件与三个选项，点击其中一个。
3. 死亡：81岁终点，无选项，进入真实告别动画与人生回顾。

Mock 只替换模型返回内容；鉴权、SSE、选项校验、状态推进、存档、恢复、告别和回顾展示都走实际链路。回顾也由本地固定内容生成，因此整个三步流程不调用模型、不需要模型 Key。

Mock 开局成本为0，沿用现有开局操作与账本事务；正常新局仍为20积分。Mock 标记由服务端写入 LifeState.flags，不接受客户端直接指定免费成本。开局幂等哈希区分 Mock 与正常请求，避免同键切换来源。

开启只影响新开的局，不能把已有真实人生突然变成三步测试。关闭 Mock 后，当前 Mock 局的下一次推进恢复真实模型，并清除该局标记，之前的历史不重写，也不追溯扣本局积分。需要再次走三步时重新开局。已生成的回顾仍读缓存。

## 积分与测试支付

遥控器内每次可给当前开发账号增加1000积分，同源、权限、幂等与限流校验保持不变。网络结果不确定时沿用原请求键重试；余额和 `developer_grant` 账本在同一事务中更新。成功后刷新服务端页面数据，不修改其他账号。

Owner 充值页另有 ¥0.01 / 20积分测试套餐，结算、创建订单、重试支付仍由服务端鉴权并确定价格。demo模式不收款、不发购买积分；live才走现有微信支付链路。本次未发起真实支付、未更改生产配置或发布。

## 验收与浏览器会话隔离

`lib/mock-routes.test.ts` 覆盖真实 start→next→ending 三步链路、零消费、回顾缓存、关闭 Mock 恢复模型、普通用户伪造 Cookie 被拒绝与退出清除 Mock。`lib/developer-mode-ui.test.ts` 验证未开启时导航不变、开启后仅增加角标和 Debug 图标，不出现工具横条或自动展开的弹窗。

本轮已使用独立本地数据库与合成账号从首页实际走通三步和告别/回顾；弹窗三项高度48px、宽度一致且无下划线。悬浮遥控器改版后未再次进行浏览器登录操作，运行代码检查与回归测试。

**本轮验收曾发生的隔离问题：** 测试端口3307与 Owner 的其他 localhost 端口共享同一域 Cookie，写入合成会话覆盖了原本地登录。测试页、进程与专用库已关闭/清理；原登录Cookie无法恢复，Owner需重新登录。后续禁止以“不同端口”充当会话隔离：必须使用与 Owner 不同的独立主机域，或经授权使用真正独立的浏览器 Cookie 配置。不清理或替换 Owner 的登录数据。
