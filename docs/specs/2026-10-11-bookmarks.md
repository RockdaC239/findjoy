# FindJoy「觅乐书签」开发文档 v0.1

日期：2026-10-11。

用途：交给另一个开发 agent 实现本次栏目。本文包含用户已明确的需求及为完成体验补充的默认方案；仅交付开发文档，本轮不实现页面。

## 1. 产品定位与范围

「觅乐书签」是 FindJoy 维护者精选的内容分享栏目，收录对寻找幸福、探索人生意义、理解自己与生活有帮助的文章、视频或其他外部内容。

第一版交付一条完整路径：**首页入口 → 独立书签列表页 → 点击卡片打开外部内容**。页面提供明确的「返回首页」入口。

用户已经明确：

- 栏目名称为「觅乐书签」。
- 入口位于首页右上角现有导航区域，见用户截图。
- 点击进入一个独立页面。
- 页面展示维护者分享的一张张内容卡片。
- 每张卡片包含封面、标题、可选介绍，点击跳转到内容地址。

本文补充的默认方案：外链新标签打开；显示来源、可选作者；使用静态内容文件维护；明确排序、空状态、封面失败兜底、响应式布局、键盘操作及验收方式。

本版不包含内容详情页、全文转载、用户投稿、后台管理、登录、收藏、评论、搜索、分类筛选、分页、支付、AI 导读或自动抓取外链元数据。内容量较少时不增加这些功能。

## 2. 首页入口

### 2.1 位置与样式

在现有右上角 `.topbar-actions` 中，按以下顺序展示：

**觅乐书签 ｜ 过往人生 ｜ 模型设置**

复用现有导航的字体、颜色、细下划线与 hover 风格。「觅乐书签」是页面导航链接，使用链接语义，不做弹窗、页面内切换或额外主按钮。

目前 `app/page.tsx` 的非事件阶段共用该导航；在此分支追加入口。人生事件阶段目前仅显示年龄，保留这一行为，避免在做选择时引入新入口。首页主文案与「开始人生」按钮不因本次任务调整。

手机端允许导航区域自适应换行；如果换行，必须相应调整容器高度，避免现有固定高度导致内容重叠。不能通过隐藏「过往人生」或「模型设置」来容纳新入口。

### 2.2 路由

| 项目 | 值 |
| --- | --- |
| App Router 文件 | `app/bookmarks/page.tsx` |
| 框架内部路由 | `/bookmarks` |
| 当前部署访问路径 | `/findjoy/bookmarks` |
| 首页实际访问路径 | `/findjoy` |

入口使用 Next.js `Link`，`href="/bookmarks"`。项目已配置 `basePath: "/findjoy"`，Next.js 会为站内 Link 自动加前缀；不要写成 `href="/findjoy/bookmarks"`，避免重复前缀。

点击入口在当前标签内导航。

## 3. 书签页面

### 3.1 页面结构与文案

1. 顶部左侧复用 `BrandLogo`，在本页面链接到首页；右侧显示「返回首页」。
2. 页面主标题：**觅乐书签**。
3. 说明：**分享关于幸福、人生意义与如何生活的好内容。**
4. 简短操作提示：**点击卡片，在新标签页打开原文或内容页面。**
5. 内容卡片列表。

返回按钮文字可以显示为「← 返回首页」，使用 `Link href="/"`。Logo 同样使用 `href="/"`；不要在本任务中修改首页 Logo 现有的展示页链接。

返回行为固定回 FindJoy 首页，不使用 `history.back()`：用户直接访问书签网址时，也必须能回首页，而不是返回别的网站。不会删除或重开已有的人生存档；回首页后沿用现有继续人生机制。无需新建跨页面游戏状态保存系统。

页面 title：`觅乐书签 | FindJoy`；description 与页面说明一致。通过本页 metadata 覆盖默认「人生模拟器」标题。

### 3.2 布局

沿用项目的纸色背景、黑色正文、灰色次要文字、橙色强调、细边框和留白，不引入新的设计体系或依赖。

- 内容容器居中，最大宽度约 1120px。
- 标题区与列表之间有清楚的间距；无需沿用首页巨大首屏留白，首张卡片应尽早可见。
- 宽屏默认 3 列，中等屏幕 2 列，窄屏 1 列；参考断点为 1024px 和 700px，实施时按卡片实际可读性调整。
- 卡片间距约 20–24px，封面宽高比统一为 16:9。
- 内容少时正常从首列排列，1 条内容不拉伸成整页巨幅展示。
- 不为留白生成假内容、重复内容或「即将上线」卡片。

## 4. 内容卡片

### 4.1 展示内容

从上到下：

1. 封面。
2. 标题。
3. 可选介绍。
4. 次要信息：可选作者、来源名称，以及外链箭头。

标题建议两行展示，超过长度可截断，但完整标题仍应存在于 DOM 中。介绍建议最多三行；为空或只有空白时不展示，也不添加「暂无介绍」。网格内卡片高度尽量一致，底部来源信息对齐。

来源名称使用维护者填写的简短名称；未填写时从链接的 hostname 展示，例如 `zhihu.com`。作者为空时省略，不产生多余分隔符。

### 4.2 跳转与可访问性

- 整张卡片使用一个原生 `<a>`，封面、标题和卡片留白都属于同一点击目标。
- `href` 使用内容的完整地址，外链设置 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 打开外部内容后，书签页留在原标签内，用户可以继续浏览。
- 不增加跳转确认弹窗、跟踪中转页面或嵌套链接按钮。
- 卡片支持键盘 Tab 聚焦与 Enter 打开，有清晰 `focus-visible` 状态；新标签打开行为需能被辅助技术获知。
- 封面与标题重复表达同一内容时使用空 alt，避免屏幕阅读器重复朗读。
- hover 使用轻微边框或文字颜色变化，不以强动画、翻面或浮层遮挡标题。
- 标题与介绍按普通文本渲染，不注入 HTML。

### 4.3 封面

封面优先使用维护者提供的本地图片，放在 `public/bookmarks/`。不自动抓取外站封面，也不依赖外站防盗链图片。

每张卡片都必须有封面区域。图片未提供、资源缺失或加载失败时，显示项目风格的默认封面（纸色或浅橙背景与简洁书签图形），保持 16:9 尺寸；不能留下破图图标、空白塌陷或令整张卡片消失。默认封面可以复用一份本地资源。

图片使用固定宽高比例与 `object-fit: cover`，避免布局跳动；列表中的图片合理使用懒加载。图片路径注意项目 `/findjoy` 前缀：与站内 Link 不同，本地图片 src 需正确处理 basePath。例如资源 `public/bookmarks/li-mu-sgd.png` 的当前部署请求路径是 `/findjoy/bookmarks/li-mu-sgd.png`。

若错误处理需要客户端代码，仅将封面或卡片提取为小型 Client Component，列表页保持 Server Component；沿用当前 Next.js 文档与项目图片约定，不额外添加图片处理依赖。

## 5. 数据与维护方式

第一版使用 `lib/bookmarks.ts` 中的一个有类型的静态数组。数组顺序就是页面顺序，新分享的内容放在数组开头；不增加排序字段、日期或数据库。

建议字段：

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| `id` | 是 | 唯一稳定标识，作为 React key |
| `title` | 是 | 内容完整标题 |
| `url` | 是 | 完整的 HTTP/HTTPS 外链，优先 HTTPS |
| `cover` | 否 | 本地封面路径；省略时展示默认封面 |
| `description` | 否 | 简短介绍或推荐理由，建议 40–100 字 |
| `author` | 否 | 原作者或创作者 |
| `source` | 否 | 来源名称，例如「知乎」 |

用户要求每个内容有封面；这里 `cover` 数据可选仅用于缺图兜底，界面上的封面区域始终存在。

维护流程：准备有权使用的封面 → 在数组开头加入一条记录 → 本地预览 → 通过验证 → 随代码部署。删除数组条目即可下架，调整数组位置即可重排。

内容链接仅允许 `http:` / `https:`。维护者新增时检查标题非空、id 唯一、URL 合法；若实现了运行时兜底，非法条目不得变成可点击的危险链接，开发验证应能发现错误。静态数据不需要构建通用配置解析系统或请求外站验证接口。

## 7. 空状态与边界

- 数组为空：显示「书签正在整理中，稍后再来看看。」并保留返回首页入口。
- 1 条、多条、长标题、无介绍、无作者、无来源均可正常布局。
- 封面失效：使用默认封面；若默认图片本身失败，仍保留纯背景封面区域，避免反复重试循环。
- 外站失效或登录限制：保持标准外链跳转，不在本站尝试抓取正文或代理绕过。
- 刷新、直接访问、浏览器前进后退：书签页与首页均可正常加载。
- 页面不请求人生生成、模型配置或存档 API，也不产生模型调用费用。

## 9. 验收标准

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A1 | 首页入口 | 在右上角「过往人生」左侧显示「觅乐书签」，现有按钮仍能正常使用 |
| A2 | 导航 | 点击后当前标签进入 `/findjoy/bookmarks`，无重复前缀、无弹窗 |
| A3 | 独立访问 | 直接输入书签页网址并刷新，页面可用，标题与介绍正确 |
| A4 | 返回首页 | 返回链接及本页 Logo 均回 `/findjoy`；从外站直接进入时也成立 |
| A5 | 卡片信息 | 李沐文章的封面、标题、介绍、作者和来源正常显示，顺序与数据一致 |
| A6 | 外链 | 点击封面、标题或卡片留白均打开同一原文地址的新标签，原书签页保留 |
| A7 | 缺图 | 模拟图片 404 后出现默认封面；卡片尺寸和链接不受影响 |
| A8 | 可选数据 | 无介绍／作者／来源、长标题和空列表都可正常显示，无虚假占位内容 |
| A9 | 响应式 | 375px 与 390px 手机宽度无横向溢出；768px、1440px 内容布局清楚，导航不重叠 |
| A10 | 键盘与辅助技术 | 导航与卡片可聚焦、可用 Enter 打开，聚焦状态可见，新标签行为可获知 |
| A11 | 游戏回归 | 过往人生、模型设置、开始／继续人生仍可使用；事件阶段原有年龄栏不被改动 |
| A12 | 隔离 | 进入书签页不调用模型或人生接口，不删除已有存档，不更改模型配置 |

开发完成后执行仓库要求的 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`，逐项报告结果。新增校验或封面兜底分支时做一项有意义的针对性验证；用浏览器验证页面交互与 basePath 资源路径，不为纯文案和样式编写镜像实现的测试。

交付至少包含首页新入口截图、桌面书签页截图、手机书签页截图，以及实际测试结果。需要提交代码时遵守 `type:中文描述` 规范，例如 `feat:新增觅乐书签内容分享栏目`。
