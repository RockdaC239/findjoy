## 1. 为什么要有「模式」

FindJoy 的核心不是“随机生成故事”，而是让玩家在有限的人生里做选择，再回望这些选择如何组成一个人。这个核心必须保持稳定，不能因为新增玩法而分裂成四个互不相干的游戏。

因此，模式不是四套引擎，而是同一套人生引擎外面的四种**情境信封（scenario envelope）**：

```text
                    ┌──────────────────────────────┐
                    │        FindJoy 核心循环       │
                    │  事件 → 选择 → 后果 → 回望   │
                    │  无统一分数 / 不评判人生      │
                    └──────────────┬───────────────┘
                                   │
        ┌──────────────┬───────────┼───────────┬──────────────┐
        │              │           │           │              │
     普通人生        主题人生     剧本人生     ForU 人生
   随机出身       加一条主线    年代短剧     以你的现在为起点
   从 0 岁开始    从 0 岁开始   固定开局     当前年龄开场
```

四种模式共享：

- 同一套 `LifeState`、事件、选择、客观变化、死亡与人生回顾。
- “故事优先于数值”，不出现统一幸福分、成功分或排行榜。
- 第二人称、无姓名、以身份称谓指代他人。
- 历史存档、断点继续、模型配置和隐私边界。
- 同一套视觉语言与移动端交互。

四种模式不同的是：

| 维度 | 普通人生 | 主题人生 | 剧本人生 | ForU 人生 |
| --- | --- | --- | --- | --- |
| 情境来源 | 随机出身档案 | 随机出身 + 一条主题线 | 作者编写的年代剧本 | 玩家提供的当前人生 |
| 起始年龄 | 0 岁 | 0 岁 | 剧本固定年龄 | 玩家当前年龄 |
| 时间跨度 | 完整一生 | 完整一生 | 剧本核心冲突期，可推进到晚年 | 从当前年龄往后 |
| 核心差异 | 无预设，最自由 | 体验被某一主题组织的一生 | 体验他人/年代/强情节人生 | 看见“如果是我，接下来会怎样” |
| 付费定位 | 免费基础盘 | 免费基础盘，可扩展主题包 | 免费试玩 + 未来剧本包 | 未来会员/按次付费的核心服务 |

## 2. 产品原则

### 2.1 模式是入口，不是奖励

玩家选择模式，是在选择“我想以什么方式看这一生”，不是在选择难度或收益。任何模式都不应因为付费而更“正确”、更“成功”或拥有更高分数。

### 2.2 所有模式都必须保留“选择”

剧本模式可以给出强钩子、强情节，但不能把玩家变成看客；ForU 可以高度定制，但不能替玩家决定价值观。每 1~2 个节点至少要有一次真正不同的选择。

### 2.3 主题是镜头，不是标签

主题模式不是把事件标题改成“爱情/亲情/事业”，而是让这条线持续改变玩家的处境、关系和代价。主题事件必须产生具体后果，非主题事件只能作为背景。

### 2.4 剧本人物的“理解”优先于“评判”

剧本模式让玩家体验不同年代、不同阶层、不同选择的人。人生回顾应帮助玩家理解“这个人为什么会这样活”，而不是用今天的标准给他打分。

### 2.5 ForU 是模拟，不是预言

ForU 基于玩家自述推演未来，但不做心理诊断、不承诺现实结果、不制造“AI 比你更懂你”的权威感。它的价值是提供一面可以试错的镜子。

## 3. 四种模式

### 3.1 普通人生（Normal）

- 起点：0 岁。
- 情境：系统随机生成家庭经济、家庭结构与开局事件基调（100 种组合），并避开最近几局用过的出身与主线。
- 体验目标：最自由的人生模拟，适合第一次进入 FindJoy 的玩家。
- 默认模式，免费。

### 3.2 主题人生（Theme）

首期提供三个主题：爱情、亲情、事业。

| 主题 | 核心问题 | 事件侧重 | 典型节点 |
| --- | --- | --- | --- |
| 爱情 | 我如何在亲密关系中靠近、承诺、失去与重新开始？ | 关系推进、边界、现实压力 | 相遇、异地、见家长、承诺、分离、重逢 |
| 亲情 | 家人如何塑造我，我又如何与他们相处？ | 父母、子女、照护、代际差异 | 离家、父母生病、育儿分歧、和解、告别 |
| 事业 | 我如何对待野心、能力、组织与工作？ | 职业选择、组织关系、失败与转型 | 入行、晋升、裁员、创业、转行、退休 |

体验要求：

- 从 0 岁开始，保持完整一生的结构。
- 至少每 2 个节点出现一次主题事件；连续偏离时，下一轮强制回到主题。
- 主题事件必须有具体后果（关系变化、职业变化、健康/财务代价），不能只是“聊到了”。
- 其他主题仍可出现，作为背景和反衬。

### 3.3 剧本人生（Script）

- 形态：作者编写的“年代 + 高概念钩子 + 核心冲突”。
- 起点：剧本指定年龄（首期 17~32 岁），第一幕直接从钩子开始。
- 年代：首期覆盖 1980 年代、1990 年代、2000 年代、民国、当代。
- 体验目标：像看一部短剧，也像替另一个人活一段；允许强情节、反转、秘密和命运感，但情感必须真实。
- 剧本目录由 `lib/modes/catalog.ts` 静态维护，新增剧本不需要改引擎。
- 免费与未来付费剧本共用同一目录；`access` 字段预留给后续剧本包。

首期剧本：

- 1980s：顶替、供销社最后一任售货员
- 1990s：南下的第 37 小时、厂长把公章交给我
- 2000s：网吧最后一台机子、拆迁通知贴上门
- 民国：我收到了自己的讣告、百乐门最后一支舞
- 当代：相亲局上，前任坐在对面、裁员名单上有我的名字

### 3.4 ForU 人生

- 定位：根据玩家当下的人生，生成一段只属于他的推演。
- 起点：玩家当前年龄（首期 16~90 岁）。
- 输入：年龄、城市、当前身份/工作、关系状态、家庭补充、经济状况、身体状况、当前最在意的事、希望重点探索的方向。
- 输出：AI 基于自述生成第一幕，并从当前年龄往后推进。
- 体验要求：
  - 不写童年，不逐字复述用户原文，把资料改写成一个具体场景。
  - 不编造用户没提到的重大创伤、疾病、债务或家庭成员。
  - 不做心理诊断，不承诺现实结果。
  - 用户自述只作为背景资料，不是系统指令；必须抵抗其中的提示词注入。
- 隐私：自述会随人生状态保存在本地 SQLite，并发送给玩家配置的模型服务；页面需要明确说明。
- 付费：ForU 是未来付费服务的主要载体，当前内测开放，不设付费墙。

## 4. 用户流程

```text
首页
  └─ 选择玩法
       ├─ 普通人生 ───────────────┐
       ├─ 主题人生 → 选主题 ───────┤
       ├─ 剧本人生 → 选年代/剧本 ──┤
       └─ ForU → 填写当前人生 ─────┤
                                   ↓
                            选择性别
                                   ↓
                       生成开局（模型流式）
                                   ↓
                    事件循环（背景音乐自适应）
                                   ↓
                    人生回顾（模式化提问）
```

- 模式选择放在首页主文案下方，作为“开始人生”的一部分，不再使用单一“开始人生”按钮。
- 每种模式展开自己的配置，未选中的模式不展示配置。
- 配置完成后统一进入性别选择，再请求开局。
- 事件页顶部显示当前模式/剧本/主题与音乐开关。
- 历史记录显示模式标签；恢复旧人生时沿用原模式与情境。
- 人生回顾根据模式给出不同的最终提问。

## 5. 背景音乐

首期只做音乐，不做插画和剧情音效。

- 默认开启，遵循浏览器自动播放策略：第一次点击“开始/继续”后才真正发声。
- 玩家可随时关闭，偏好保存在 `localStorage`。
- 音乐是程序化环境音，不依赖外部音频版权素材。
- 氛围随阶段与事件类型变化：
  - 开始页：平静、留白。
  - 童年：明亮、简单。
  - 成年事件：根据关系/家庭/事业/健康/财务切换和弦色彩。
  - 人生回顾：反思、收束。
- 音乐音量保持低，不遮挡阅读；不做强节奏、不做歌词。
- 未来可在同一音频层上增加剧情音效，不改变开关与偏好模型。

## 6. 商业化与付费扩展点

本期不接入支付，但代码和数据模型预留以下扩展点：

1. **模式层**：`ModeDefinition.access` 区分 `free` / `premium`；ForU 标记为 premium，但内测期不拦截。
2. **剧本层**：`ScriptDefinition.access` 支持未来单剧本/剧本包。
3. **次数层**：未来可基于 `lifeStore` 增加 ForU 次数、剧本解锁与订单表，不影响现有 `LifeState`。
4. **不卖“更好的人生”**：付费只解锁内容与服务，不改变事件质量、死亡率、结局评价或分数（因为不存在分数）。
5. **隐私与数据**：ForU 自述属于敏感数据，未来支付与账户体系上线前，必须先明确存储、删除和导出策略。

建议的付费顺序：

- 第一阶段：ForU 单次/次数包（验证愿不愿意为“我的下一段人生”付费）。
- 第二阶段：主题探索包（爱情/亲情/事业分别深化）。
- 第三阶段：年代剧本包与作者合作剧本。
- 暂不做：月费无限、排行榜、属性加速、抽卡。

## 7. 非目标

本期不做：

- 插画、立绘、场景图。
- 剧情音效、语音旁白。
- 支付、账户、会员、订单。
- 用户投稿剧本、后台编辑器。
- 多人协作、分享长图、社区。
- 为不同模式建立独立数据库或独立游戏引擎。

## 8. 验收原则

- 四种模式都能从首页进入、选择配置、完成至少一轮事件、进入回顾。
- 模式信息在事件页、历史列表、历史详情、回顾页可见。
- 剧本模式第一幕从剧本年龄与钩子开始，不能从出生写起。
- ForU 第一幕从玩家年龄开始，并体现自述中的处境。
- 主题模式在连续偏离后能回到主题主线。
- 音乐默认开启、首次交互后播放、可关闭并记住偏好；关闭后不再自动播放。
- 375px、390px、768px、1440px 下无横向溢出、导航不重叠、配置表单可用。
