# FindJoy 觅乐设计系统

版本：1.0 · 2026-11-03。覆盖手机端、平板端与桌面端；当前交付载体是响应式 Web，设计规则分别处理触控与鼠标/键盘。手机端是独立使用场景，不能只作为桌面端缩小后的兜底。产品像一本可以继续写的人生故事：安静、清晰、有温度，留白给阅读，橙色留给选择。

设计意图以本文件为准，精确数值以 [tokens.json](tokens/tokens.json) 为准，组件外观与状态见 [Showcase](showcase/index.html)。[原品牌页](../app/brand/page.tsx)（运行路径 `/findjoy/brand`）保留，是本系统品牌章节的原始依据。品牌资产继续复用 `components/BrandLogo.tsx`、`public/findjoy-logo.svg` 和 `app/icon.svg`。

## 1. 依据与维护边界

- **Owner 已确认**：现有纸白/墨色/橙色方向、原品牌页；本轮充值页反馈见第 2 节。它们是当前明确偏好，不推断成对所有产品的永久喜好。
- **现有实现提取**：字体、细描边、圆角层级、叙事与账户布局、控件高度、阴影和动效。来源与历史差异见 [界面审计](references/ui-audit.md)。
- **系统整理**：将零散数值归入语义 token；新界面优先按此执行。已有页面分步迁移，不能把设计样例当成所有页面已经完成整改。
- 本次已将全站六个基础色变量接到 tokens，保持原值。其他旧样式仍在 `app/globals.css`；不重写业务页、品牌页、身份、付费或游戏逻辑。
- 不创建第二套组件库，不引入 UI 框架。先复用项目现有组件，再使用原生平台能力。

## 2. 已确认的设计习惯

| 规则 | 明确依据 | 后续执行方式 |
| --- | --- | --- |
| 标题末尾不加句号，内部逗号保留 | 充值页标题改为「给好奇心，多一点可能」 | 适用于展示型标题；正文正常标点；品牌字标的句点独立处理 |
| 强调先用字色 | Owner 否定折合价的底色框、放大与加粗，保留橙色字色 | 折合价/节省说明不额外套框，不擅自提高字号或加粗 |
| 统一尺寸不等于统一颜色 | 积分说明按钮要与余额胶囊同尺寸，仍保留橙底白字 | 同组控件高度、圆角、内边距一致；信息与操作保留各自语义颜色 |
| 居中要共享同一中轴 | 顶部标题、赠送说明、积分和说明按钮组对齐 | 标题区与主内容区对齐；按钮组整体居中，不单独偏移某个元素 |

| 手机首屏先给核心操作 | 登录页卡片被挤到首屏外，要滚动才能登录 | 手机上装饰性内容（插画、标语、权益清单、长引言）隐藏或压缩，核心卡片与主按钮首屏完整可见 |
| 手机导航收进账户菜单 | 顶栏导航被挤成第二行、位置失衡 | ≤767px 用 `AccountNav` 的 `collapseOnMobile`：只留品牌 + 头像/菜单，桌面端继续铺开 |
| 标题层级不可倒挂 | 手机端模式标题 30px 比主标题还大 | 主标题手机单行 `clamp(24px,7.4vw,32px)`；区块标题手机 22px，任何下级标题不得大于主标题 |
| 主操作跟随区块标题 | 开始按钮整行铺满，19px 文案抢标题 | 按钮放标题行右侧，手机 13px/40px、桌面 14px/44px，文案统一「开始人生」 |
| 未完成功能先隐藏入口 | 音乐未完成、模型设置暂不对外 | 用 `lib/feature-flags.ts` 开关隐藏入口，保留实现，恢复时只改 flag |

## 3. 品牌：保留原作者的设计

### 字标 DNA

- 小写 `findjoy`，末尾独立句点；DM Sans / 600 / 字距 `-0.06em` / 行高 1。
- 导航标准 18px，compact 16px；导航触控区域至少 44px，不能用放大字标来凑点击区。
- 品牌句点 `#ff5a1f` 是情绪锚点，不受“标题不加句号”影响。不要删除、换成圆点图标、分离或随意改变字距。
- 纸白底：墨黑字 + 橙色句点。墨黑底：纸白字 + 橙色句点。原品牌页的橙底变体：白字 + 墨色句点，以保留对比。
- 橙色整面背景仅作品牌变体样例，不升级为产品页面长期背景。
- 系列产品沿用同字重、同字距与字标结构，系列名接在主名之后；句点仍归属 findjoy。原页示例为 `findjoy. · studio`。
- 原品牌表达「Find joy. / 然后把它带去每一个产品。」及 `One mark. Many ways to find joy.` 保留在 `/brand`，不因新规范机械改写原创页面。

### 复用方式

业务页使用 `<BrandLogo href="/" />`，密集导航使用 `compact`。不要在新页面手写另一个 Logo。静态 showcase 仅展示同规格字标样本，不替换实际组件或 SVG；保留资产内原作者的实现。

## 4. 颜色与角色

| 角色 | 值 | 用法 |
| --- | --- | --- |
| 页面纸白 | `#f8f8f6` | 主画布，承担大部分面积 |
| 温白表面 | `#fffdf9` | 卡片/购买区，轻轻与画布区分 |
| 柔和表面 | `#ecebe6` | 信息提示、disabled 容器、次级区域 |
| 推荐表面 | `#fff9f3` | 少量推荐/选中卡片 |
| 主文字 | `#11110f` | 标题、正文、金额 |
| 次文字 | `#6d6b63` | 补充说明，不用于关键操作的唯一提示 |
| 细边线 | `#d9d7d0` | 1px 分隔与轮廓 |
| 品牌/操作橙 | `#ff5a1f` | 品牌句点、主操作、少量强调、焦点环 |
| 可读强调 | `#9d3814` | 暖色状态文字/警告说明 |
| 错误 | `#b42318` | 校验失败和可恢复错误，配可执行说明 |

面积策略：纸白与温白占主导，墨色组织内容，橙色只标出关键落点。没有必须凑满的配色百分比。状态不得只靠颜色表达，成功用明确文字与中性表面即可，不新增绿色庆祝系统。微信绿色只属于支付渠道图标，不作为全局成功色。奖励不等于分数，不引入排行榜或成就仪表盘。

**对比度边界**：现有品牌橙配白色小字、橙色小字配纸白，尚不能作为普通正文 AA 对比度合格的组合。这里如实保留已确认的品牌值与操作外观，不声称已经通过无障碍认证。新增长说明使用墨色；需要 AA 小字强调时使用 `accent-readable`。现有橙色 CTA/折合价的小字对比度列为待校准项，调整品牌操作色须先与 Owner 确认，不能自行换色。

不增加产品背景渐变、玻璃效果、发光边框、彩色模糊光团。既有 `/showcase` 演讲页的照片 + 墨色遮罩是独立展示场景的已选方向，不向账户/游戏 UI 扩散；素材来源见 [许可记录](references/showcase-image-attribution.md)。

## 5. 字体与文字层级

| 角色 | 字体 / 尺寸 | 字重 / 行高 |
| --- | --- | --- |
| 首页展示标题 | DM Serif Display, Georgia, serif / `clamp(36px,6vw,72px)`；手机 `clamp(24px,7.4vw,32px)` 单行 | 400 / 1.2 |
| 账户/充值页标题 | 同展示字体 / `clamp(30px,4.6vw,58px)` | 400 / 1.35 |
| 分区标题 | DM Sans, sans-serif / 24px | 500 / 1.35 |
| 阅读正文 | UI 字体 / 16px | 400 / 1.8 |
| 界面文字 | UI 字体 / 14px | 500 / 1.55 |
| 辅助文字 | UI 字体 / 12px | 400 / 1.6 |
| 英文眉题 | UI 字体 / 10px | 600 / 字距 0.14em |

DM 字体不覆盖完整中文字形，中文由操作系统的 serif/sans-serif 回退提供；不同设备可能有差异，不宣称已经嵌入统一中文字体。DM Sans 与 DM Serif Display 已自托管（`app/fonts/`，OFL-1.1），不再依赖 Google Fonts，手机网络下不会退回系统英文字体；展示字体栈显式声明 `Songti SC` / `Noto Serif SC` 等中文衬线回退，避免 iOS 把标题回退成黑体。展示标题有文学感，按钮和说明清楚克制。不要把 Logo 的负字距复制给正文。价格可用现有 48px 层级；辅助折合价保持辅助层级和橙色，不与主价格竞争。

措辞直接、具体，按钮用动词；金额、局数与积分使用真实业务配置。展示样例是静态示意，不作商品定价来源。

## 6. 间距、布局、密度

- 新组件使用 4px 基础刻度：4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 / 40 / 48 / 64 / 96px。不为统一刻度批量改写旧页的 22px 等值。
- 桌面外边距 `clamp(24px,5vw,80px)`；手机 22px。普通内容最大 1100px，故事阅读 760px，模式入口 960px，说明弹窗 460px。
- Roomy：32px，开场与回顾；Balanced：24px，账户和购买；Compact：16px，导航/历史元信息。紧凑不等于缩小触控目标。
- 主任务单一：开场 → 出生/早年 → 事件与选择 → 回顾。叙事先于数值，价格先于营销说明。
- 充值卡桌面四列，中等宽度两列，手机单列。模式卡保留已有独立规则，不能为了统一四列覆盖手机模式选择。
- 同排余额与操作用 flex 整体居中、`align-items:stretch`、相同 padding/圆角；余额的大数字撑高后，旁边按钮仍等高。允许自然换行，不锁导航/分组高度。
- 弹窗标题和说明左对齐；外层英雄区居中不能污染弹窗。必要信息可滚动，按钮不得被遮挡。

## 7. 基础组件与状态

### 按钮与胶囊

- 主操作：橙底白字，1px 同色描边，最小高 48px，圆角 12px，无常驻阴影。hover 用墨色；pressed 微下沉 1px；focus 为 2px 橙色外环 + 3px offset。
- 次操作：透明/纸白表面，墨字或次文字，细描边；不与主操作争夺面积。
- 胶囊：同组余额与说明按钮共用最小高 48px、9px 20px 内边距、完全圆角；余额为中性信息，说明按钮仍为橙底白字。
- 纯图标控制至少 44×44px，必须有可访问名称。hover 只是反馈，不能成为唯一入口。
- disabled：禁用语义 + 0.7 opacity；loading：保留宽度和操作名称，使用 `aria-busy` 并阻止重复提交。
- danger：明确动作文字、错误色与可恢复说明；不要用品牌橙把所有状态涂成“推荐”。

### 表单

复用现有字段形式，明示 label；输入最小高 48px，圆角 12px，纸白/温白底、1px 细描边。focus 2px 橙环。helper 12px 次文字；错误消息就地显示并使用 `aria-describedby`/`aria-invalid`；placeholder 不能代替 label。多行输入给足正文空间，不记录敏感输入到日志或展示样例。

### 卡片

温白表面、1px 细边线、20px 圆角、24px padding、无阴影；推荐态只加橙色边线和淡暖色底。面板可用 24px 圆角；弹窗 20px。已有历史弹窗的 16px 记录为旧实现，不立即全站替换。

强调信息先用文字和层级，不为每句话套一个新容器。卡片已经是表面时，不再在外面包一张有底色/边框/阴影的“展示卡”。按钮、输入等原子控件可以放在一个系统表面上展示。

### 导航、对话框与反馈

导航可换行且高度自适应，保留必要入口；当前页面不重复展示指向自己的充值入口。手机端开始页把导航项收进头像/菜单下拉（`AccountNav` 的 `collapseOnMobile`），顶栏只留品牌与账户，避免导航被挤成第二行；桌面端继续铺开。弹窗优先原生 `<dialog>` 的 `showModal()`，提供明确关闭按钮和 Esc、焦点约束及关闭后焦点回到入口。默认不靠点空白区域才能关闭。

错误给下一步；空状态解释现状并给必要操作；成功反馈低调、明确。不伪造订单成功、倒计时优惠或用户数据。

## 8. 深度与动效

- 常规卡片、按钮：无阴影；不要把所有元素做成悬浮面板。
- 浮层：`0 8px 30px rgba(17,17,15,.12)`；模态：`0 16px 50px rgba(17,17,15,.15)`；sticky 继续按钮可用 HUD 阴影。
- 遮罩：`rgba(17,17,15,.5)`；焦点环独立于阴影。
- 常用动效 150–200ms / ease；hover 上移最多 2px，pressed 下移 1px。无自动播放的营销轮播和无意义反复漂浮。
- `prefers-reduced-motion:reduce` 下移除位移动画与旋转加载动画，仍保留可读状态。既有环境音乐独立遵循手势门控和用户偏好，不通过设计系统改变。

## 9. 手机与平板端设计

### 手机：阅读与单手操作优先

- **视口与留白**：布局宽度随实际设备，320px 起不横向溢出。左右默认 22px；内容紧凑处使用 16px 内边距。不要把 390px 预览样例当成手机页面固定宽度。
- **标题与正文**：移动标题按角色在 24–36px 内取值：内容页标题 30–36px，首页主标题为保一行用 `clamp(24px,7.4vw,32px)`；正文 16px / 1.8，必要辅助信息至少 12px。10px 眉题仅作装饰标签，不能承载关键金额/入口/错误。
- **触控与反馈**：纯图标至少 44×44px，主要按钮/表单至少 48px。必须有 pressed、focus、disabled/loading 反馈；不依赖 hover 才出现入口，不能让按钮文字溢出触控区域。
- **导航与分组**：必要入口全部可达；桌面端铺开，手机端（≤767px）收进头像/菜单下拉，顶部只留品牌与账户，不再让导航挤成第二行。菜单支持点击展开、关闭与键盘返回，触控目标 ≥44px。余额和说明按钮成组居中，同排等高，放不下自然换行，不能截断积分数值。
- **首屏优先核心操作**：手机首屏必须能完成当前页面的主任务（登录页的登录卡、开始页的开始按钮），不能让用户先滚动。曲线插画、页脚标语、权益清单、三行引言这类装饰性内容在手机端隐藏或压缩，桌面端可以保留。
- **标题层级**：主标题在手机上一行显示（首页 `clamp(24px,7.4vw,32px)`）；区块标题（如「普通模式」）手机 22px、桌面 `clamp(28px,3vw,38px)`，任何下一级标题都不得在视觉上压过主标题。
- **主操作位置**：开始/提交这类主操作放在所属区块标题同一行右侧，尺寸随标题层级收敛，不整行铺满、不抢标题重量；手机 13px/40px、桌面 14px/44px，文案统一「开始人生」。
- **登录与账户页**：登录卡是唯一核心操作，手机端压缩文案区并隐藏曲线插画、页脚标语和权益清单，保证整张卡片和登录按钮首屏可见。
- **叙事与选择**：正文单列，选项支持完整换行，选择卡可整块点选；不要用横向滚动藏关键选项。事件年龄/模式等元信息可换行，不抢正文的层级。
- **购买**：套餐纵向单列；价格、积分/局数、折合价与操作顺序固定。单次购买区在窄屏纵向展开，购买按钮占可用宽度。标准包推荐仍清楚可见，不能靠桌面列位置表达推荐。
- **弹窗**：最大宽度 `min(460px,100% - 32px)`，最大高度 `100dvh - 32px`；标题与正文左对齐、内容可滚动、关闭按钮可达。长说明不锁死在一屏；保留原生焦点约束与 Esc。
- **安全区与软键盘**：底部动作区追加 `env(safe-area-inset-bottom,0px)`，必要顶栏考虑顶部安全区。使用动态视口高度；输入框聚焦后应能滚动到字段与错误说明。不要用固定定位把提交按钮压到软键盘下。
- **底部操作**：默认留在文流；仅持续推进等确有需要的任务使用 sticky，底部间距至少 16px + 安全区，并给正文留出按钮高度。不得同时叠多个悬浮购买按钮。

### 平板：保持阅读尺度

平板不等于放大的手机或缩小的桌面。账户/充值可用两列，故事仍限制在 760px 阅读宽度；导航和控件沿用触控目标，长弹窗限制宽度。横竖屏变化时允许重排，不能固定单一设备高度。

### 响应式映射与验证

| 场景 | 主要组织方式 | 必查内容 |
| --- | --- | --- |
| 手机窄屏（含 320–430px） | 故事/套餐单列、选项完整换行 | 主操作首屏可见、长昵称/金额、导航收进菜单、弹窗、触控、安全区、软键盘 |
| 手机横屏 / 小平板 | 依内容容纳能力决定一列或两列 | 短视口弹窗可滚动、不裁操作 |
| 平板（约 768px） | 购买两列、故事限宽 | 横竖屏、触控入口、分组对齐 |
| 桌面（约 1024px 以上） | 购买四列、故事居中限宽 | 鼠标与键盘、焦点、hover 非唯一入口 |

这些是布局目标；现有页面的 700/767/900/1023px 等断点按实际内容保留，不为统一数字盲目改写。新增或修改界面必须同时审视手机与桌面；截图仅在 Owner 明确要求时产出。移动端浏览器验收不等于原生 iOS/Android 或真实软键盘已验证。

## 10. 给未来 AI 的工作入口

1. 先读本文件、`tokens/tokens.json`，再看 showcase；只读目标页面与邻近复用组件。
2. 优先复用 `BrandLogo`、`AccountShell`、`AccountNav`、已有表单与对话框，不能新造一个平行设计框架。
3. 具体值改 JSON 后运行 `npm run design:tokens`，`tokens.css` 不手改；TypeScript 从 `tokens.ts` 读取同一 JSON。
4. CSS 使用 `--fj-*` 语义 token；旧的 `--paper/--ink/--muted/--line/--orange/--soft` 是兼容别名，不创建第二份基础值。
5. 改新组件或已有页面时逐步接入，不借整理设计系统改动价格、登录或模式规则。
6. Owner 对视觉的反馈只改授权部分：提亮字色不等于加框；同尺寸不等于换色；不要把局部喜好推成无条件全站重设计。
7. 后续视觉反馈若形成新规则，先给出具体调整结果并确认是否回写规则、tokens 和 showcase。当前版本的正式整理已由 Owner 授权。

示例指令：

> 按 FindJoy 设计系统制作普通模式入口。使用纸白画布、墨色标题、温白无阴影卡片、少量橙色主操作；展示型标题末尾无句号；按钮最小高 48px；说明左对齐。复用现有组件，保留手机导航与触控入口，不增加评分。

## 11. 检查与待迁移项

每次检视颜色角色、字号层级、边线/圆角、留白、状态和对齐；同时检查手机/平板的换行、长内容、触控和溢出，以及首屏能否完成主任务（登录、开始人生）。装饰性内容可以按设备隐藏或压缩；必要入口不能消失，收进账户菜单不算隐藏；未完成功能用 `lib/feature-flags.ts` 隐藏，功能完成时恢复。

- `npm run design:check`：确认 CSS 与 JSON 同步。
- `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`：项目验证；数据库测试使用独立 `TEST_DATABASE_URL`。
- standalone showcase 可直接打开 `design/showcase/index.html`，不依赖后端与账户。字体联网不可用时自然回退。
- 浏览器视觉验收按 Owner 要求执行；未进行时必须如实说明，静态检查不等于视觉验收。
- 待迁移：橙色小字对比度、旧页不统一字号/圆角/焦点态、中文字体跨设备差异；按页面逐步处理，不能在本次悄悄全站换色或换字体。
